# EmployeeBankRestApi - Database Schema Documentation

## 1. Overview

The **EmployeeBankRestApi** uses Microsoft SQL Server as the persistent data storage system.

The application uses:

- Spring Data JPA
- Hibernate
- Microsoft SQL Server JDBC Driver

The application contains two main entities:

- `Employee`
- `Account`

The database supports two major functional areas:

- Employee Management
- Bank Account Management

The Employee APIs perform CRUD operations on employee records, while the Account APIs perform banking operations such as deposit, withdrawal, and balance inquiry.

---

3. Employees Table
Table Name
employee_details7

The employee_details7 table stores employee information managed through the Employee REST APIs.

Columns
Column	Java Type	Description	Constraint
id	Integer	Unique employee identifier	Primary Key, Identity
name	String	Employee name	Required, Maximum 100 characters
email	String	Employee email address	Required, Unique, Maximum 100 characters
department	String	Employee department	Required, Maximum 100 characters
salary	Double	Employee salary	Required, Positive
4. Employee Primary Key

The primary key of the employee table is:

id

The ID is automatically generated using the JPA identity strategy.

Example:

@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Integer id;

When a new employee is created, the application does not need to provide the ID.

Example:

POST /api/v1/employees

The database automatically generates the employee ID.

5. Employee Name

The name column stores the employee's name.

Example:

Satyaprakash Samantray

The employee name is required when creating or updating an employee.

Validation is implemented using:

@NotBlank(message = "Name is required")
@Size(max = 100, message = "Name cannot exceed 100 characters")

Invalid or missing employee names result in:

400 Bad Request
6. Employee Email Constraint

The email column stores the employee's email address.

The email must:

Not be blank
Have a valid email format
Be unique
Not exceed 100 characters

Validation:

@NotBlank(message = "Email is required")
@Email(message = "Invalid email format")
@Size(max = 100, message = "Email cannot exceed 100 characters")

Example:

satyaprakash@gmail.com

The application checks for duplicate emails before creating an employee.

If a duplicate email is submitted:

409 Conflict
7. Employee Department

The department column stores the department assigned to an employee.

Example:

IT

Validation:

@NotBlank(message = "Department is required")
@Size(max = 100, message = "Department cannot exceed 100 characters")

The department is stored as a string value in the employee table.

8. Employee Salary

The salary column stores the employee's salary.

Example:

55000

Validation:

@Positive(message = "Salary must be greater than zero")

The application also applies a business rule requiring the salary to be at least 1000.

Salary >= 1000

If the salary violates validation or business rules, the API returns an appropriate error response.

Account Database Schema
9. Accounts Table
Table Name
account_details7

The account_details7 table stores bank account information used by the Account REST APIs.

The Account API provides:

Deposit
Withdraw
Get Balance
Columns
Column	Java Type	Description	Constraint
id	Integer	Unique account identifier	Primary Key, Identity
accountHolderName	String	Account holder name	Required
accountNumber	String	Unique account number	Required, Unique
balance	Double	Current account balance	Required
10. Account Primary Key

The primary key of the account table is:

id

The ID is automatically generated by the database using JPA identity generation.

JPA configuration:

@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Integer id;

Each account therefore has a unique identifier.

Example:

Account ID = 1
11. Account Holder Name

The accountHolderName column stores the name of the account holder.

Example:

Satya Samantray

The field is required by the database entity:

@Column(nullable = false)
private String accountHolderName;
12. Account Number

The accountNumber column identifies the bank account.

Example:

ACC1001

The account number must be unique.

JPA configuration:

@Column(nullable = false, unique = true)
private String accountNumber;

Example account numbers:

ACC1001
ACC1002
ACC1003

Two accounts cannot use the same account number.

13. Account Balance

The balance column stores the current balance of an account.

Example:

25000.00

The balance changes when deposit and withdrawal operations are performed.

Deposit
New Balance = Current Balance + Deposit Amount

Example:

Current Balance = 10000
Deposit Amount  = 5000
New Balance     = 15000
Withdrawal
New Balance = Current Balance - Withdrawal Amount

Example:

Current Balance = 15000
Withdrawal      = 3000
New Balance     = 12000
14. Deposit Validation

The deposit request contains an amount.

Validation:

@NotNull(message = "Amount is required")
@DecimalMin(value = "0.01", message = "Amount must be greater than zero")
private Double amount;

Example:

{
  "amount": 5000.00
}

The deposit amount must be greater than zero.

15. Withdrawal Validation

The withdrawal request contains an amount.

Validation:

@NotNull(message = "Amount is required")
@DecimalMin(value = "0.01", message = "Amount must be greater than zero")
private Double amount;

Example:

{
  "amount": 5000.00
}

The withdrawal amount must be greater than zero.

16. Account Balance Business Rule

A withdrawal is permitted only when sufficient balance is available.

Example:

Current Balance = 5000
Withdrawal      = 7000

Since:

7000 > 5000

the withdrawal is rejected.

The application throws:

BusinessException

with the message:

Insufficient balance.

The API returns:

400 Bad Request

Database Access
19. Database Access Architecture

The application uses Spring Data JPA and Hibernate to access SQL Server.

The database access flow is:

REST Controller
       |
       v
Service Layer
       |
       v
Repository Layer
       |
       v
Spring Data JPA
       |
       v
Hibernate
       |
       v
Microsoft SQL Server

The Controller layer does not directly access the database.

The Service layer communicates with the Repository layer, and the Repository layer performs database operations using JPA/Hibernate.

20. Employee Repository

The Employee entity is accessed using:

EmployeeRepository

Repository declaration:

public interface EmployeeRepository extends JpaRepository<Employee, Integer> {
}

The repository provides standard database operations such as:

save()
findAll()
findById()
delete()

The application also defines:

Optional<Employee> findByEmail(String email);

boolean existsByEmail(String email);

These methods are used for employee lookup and duplicate email validation.

21. Account Repository

The Account entity is accessed using:

AccountRepository

Repository declaration:

public interface AccountRepository extends JpaRepository<Account, Integer> {
}

The repository provides standard database operations such as:

save()
findAll()
findById()
delete()

The application also defines:

Optional<Account> findByAccountNumber(String accountNumber);

This method is used to find an account using its account number.
