EmployeeBankRestApi - Database Schema Documentation
1. Overview

The EmployeeBankRestApi uses Microsoft SQL Server as the persistent data storage system.

The application uses Spring Data JPA and Hibernate to communicate with the database.

The application contains two main entities:

employees
accounts

The database supports two major functional areas:

Employee Management
Bank Account Management

The Employee APIs perform CRUD operations on employee records, while the Account APIs perform banking operations such as deposit, withdrawal, and balance inquiry.

3. Employees Table

Table name:

employees

The employees table stores employee information managed through the Employee REST APIs.

Columns
Column	Java Type	Description	Constraint
id	Long	Unique employee identifier	Primary Key, Identity
name	String	Employee name	Required
email	String	Employee email address	Required, Unique
salary	BigDecimal	Employee salary	Required
4. Employee Primary Key

The primary key of the employees table is:

id

The ID is automatically generated by SQL Server using the JPA identity strategy.

JPA configuration:

@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;

When a new employee is created, the application does not need to provide the ID.

Example:

POST /api/v1/employees

The database automatically generates the employee ID.

5. Employee Name

The name column stores the employee's name.

Example:

Rahul Sharma

The employee name is required when creating or updating an employee.

An empty or missing employee name results in a validation error.

Expected HTTP status:

400 Bad Request
6. Employee Email Constraint

The email column stores the employee's email address.

The email is required and must be unique.

email cannot be NULL
email must be unique
email must have a valid format

Example:

rahul@example.com

The application validates the email format before saving the employee.

If a duplicate email is submitted, the application returns:

409 Conflict
7. Employee Salary

The salary column stores the employee's salary.

Salary is required and must contain a valid positive value.

Example:

50000

The validation rules are:

Salary cannot be NULL
Salary must be greater than zero

Invalid salary values result in:

400 Bad Request
8. Accounts Table

Table name:

accounts

The accounts table stores bank account information used by the Account REST APIs.

The Account API provides the following operations:

Deposit
Withdraw
Get Balance
Columns
Column	Java Type	Description	Constraint
id	Long	Unique account identifier	Primary Key, Identity
account_number	String	Unique account number	Unique
balance	BigDecimal	Current account balance	Required
9. Account Primary Key

The primary key of the accounts table is:

id

The ID is automatically generated by SQL Server.

JPA configuration:

@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;

Each account therefore has a unique identifier.

Example:

Account ID = 1
10. Account Number

The account_number column identifies the bank account.

Example:

ACC100001

The account number must be unique so that two accounts do not use the same account identifier.

Example:

ACC100001
ACC100002
ACC100003
11. Account Balance

The balance column stores the current balance of an account.

Example:

25000.00

The balance changes when deposit and withdrawal operations are performed.

Deposit
New Balance = Current Balance + Deposit Amount

Example:

Current Balance = 10000
Deposit Amount  = 5000

New Balance     = 15000
Withdrawal
New Balance = Current Balance - Withdrawal Amount

Example:

Current Balance = 15000
Withdrawal      = 3000

New Balance     = 12000
12. Account Balance Validation

The application validates the account balance during banking operations.

A withdrawal is permitted only when sufficient balance is available.

Example:

Current Balance = 5000
Withdrawal      = 7000

Since:

7000 > 5000

the withdrawal is rejected.

The API returns:

400 Bad Request

with the message:

Insufficient balance.

15. Database Access Architecture

The application uses Spring Data JPA and Hibernate to access the database.

The database access flow is:

REST Controller
       |
       v
Service Layer
       |
       v
Repository Layer
       |
       v
Spring Data JPA
       |
       v
Hibernate
       |
       v
Microsoft SQL Server

The Controller layer does not directly access the database.

The Service layer communicates with the Repository layer, and the Repository layer performs database operations using JPA/Hibernate.

24. Schema Management

The database schema is managed through JPA/Hibernate configuration.

Configuration file:

src/main/resources/application.yml

The application uses the following Hibernate schema management setting:

spring:
  jpa:
    hibernate:
      ddl-auto: update

The update setting allows Hibernate to update the database schema according to the entity mappings when the application starts.
